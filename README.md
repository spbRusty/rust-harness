# rust-harness

Локальная обвязка на Rust для работы с небольшими языковыми моделями и построения поверх них агентских систем.

Проект начинается без привязки к конкретной задаче. Сейчас основная связка — **Rust + Ollama + локальная модель**. В дальнейшем на это ядро можно добавлять оркестратор, инструменты, MCP-серверы, память, тестирование и адаптеры под разные типы проектов.

## Что уже есть

- подключение к Ollama через HTTP;
- выбор локальной модели через конфигурацию;
- агентский цикл: **задача → модель → инструмент → результат → модель**;
- встроенные инструменты для чтения, записи и просмотра файлов;
- ограничение файловых инструментов рабочей директорией;
- подключение внешних MCP-серверов через stdio;
- получение списка MCP-инструментов и их вызов;
- единая конфигурация проекта;
- базовый CLI;
- проверка сборки через GitHub Actions.

## Зачем проект

Идея не в том, чтобы сделать ещё один большой фреймворк для ИИ.

Задача — получить небольшое собственное ядро, которое можно запускать локально и постепенно расширять:

```text
локальная модель
      ↓
   Rust Harness
      ↓
  оркестратор
      ↓
 инструменты
      ↓
результаты / тесты
      ↓
   следующий шаг
```

Модель при этом не должна быть жёстко связана с конкретным проектом. Позже одну и ту же основу можно использовать, например, для разработки игр, работы с 1С, программирования и других задач.

## Требования

Нужны:

- Rust;
- Ollama;
- установленная локальная модель.

## Быстрый запуск

Клонировать репозиторий:

```bash
git clone https://github.com/spbRusty/rust-harness.git
cd rust-harness
```

Создать конфигурацию:

```bash
cp harness.toml.example harness.toml
```

Запустить Ollama и загрузить модель:

```bash
ollama serve
ollama pull qwen2.5:7b
```

Проверить доступные модели:

```bash
cargo run -- models
```

Запустить задачу:

```bash
cargo run -- run "посмотри файлы проекта и кратко объясни его структуру"
```

По умолчанию рабочая директория — текущая. Встроенные файловые инструменты не должны позволять агенту выйти за её пределы.

## Конфигурация

Основной файл — `harness.toml`.

Пример:

```toml
[model]
endpoint = "http://127.0.0.1:11434"
name = "qwen2.5:7b"

[workspace]
path = "."

[[mcp]]
name = "example"
command = "npx"
args = ["some-mcp-server"]
```

Модель можно заменить на любую другую модель, доступную через Ollama.

## MCP

MCP используется как внешний слой инструментов.

Harness запускает MCP-сервер отдельным процессом через stdio, выполняет инициализацию, получает список доступных инструментов и может передавать вызовы этим инструментам.

Схема:

```text
Rust Harness
     │
     ├── встроенные инструменты
     │
     └── MCP
          ├── Playwright
          ├── браузерные инструменты
          ├── GitHub
          └── другие MCP-серверы
```

MCP не привязан к Roblox, 1С или какому-либо другому типу проекта.

## Архитектура

```text
                    ┌──────────────┐
                    │    Ollama    │
                    │ локальная    │
                    │    модель    │
                    └──────┬───────┘
                           │
                           ▼
                    ┌──────────────┐
                    │ Rust Harness │
                    │              │
                    │ agent        │
                    │ tools        │
                    │ workspace    │
                    │ config       │
                    └──────┬───────┘
                           │
                 ┌─────────┴─────────┐
                 ▼                   ▼
          встроенные tools          MCP
                 │                   │
          файлы / workspace     внешние серверы
```

## Куда развивается проект

Порядок развития специально оставлен открытым.

Планируемые направления:

1. более надёжный structured tool calling;
2. нормальный оркестратор задач;
3. shell и запуск тестов;
4. Git-инструменты;
5. память и состояние проекта;
6. подключение дополнительных MCP-серверов;
7. адаптеры для конкретных сред и проектов;
8. более строгая система разрешений для инструментов.

Пока проект не пытается заранее решить, каким именно будет конечный сценарий использования.
